# URL管理・位置情報取得・HTTP 301転送

GitHub Pages + Google Apps Script + Google スプレッドシート + Cloudflare Workers で動かす個人用Webアプリです。

## 動作の流れ

1. 管理画面で、URL識別文字・相手に表示する文章・HTTPSの転送先・有効期限・待ち時間を設定してURLを発行します。
2. 相手が `https://<WorkerのURL>/r/<識別文字>` を開くと、白背景に文章だけの画面が表示されます。
3. 画面には、位置情報を許可した場合に緯度・経度・精度が管理者へ送信され、取得後に指定サイトへ移動することを明示します。
4. ブラウザ標準の位置情報許可が出ます。許可された場合だけGASへ位置情報を送信します。
5. 保存が成功すると、待ち時間の後に `/go/<識別文字>` へ移動します。
6. `/go/<識別文字>` はHTTP **301 Moved Permanently** と `Location` ヘッダーで設定先へ転送します。

拒否・タイムアウト・保存失敗の場合は位置情報を送信せず、転送もしません。

## 必要なサービス

- GitHub Pages：管理画面
- Google Apps Script：管理者認証、URL設定、位置情報保存
- Google スプレッドシート：URL一覧と位置情報履歴の保存
- Cloudflare Workers：専用URLの受付とHTTP 301応答

GASはHTTPステータスを任意に指定できる通常のリダイレクトサーバーではないため、HTTP 301を返す役割をCloudflare Workerに分けています。

## 1. Google Apps Scriptを準備

1. `https://script.google.com/` で新しいプロジェクトを作成します。
2. 最初からあるコードを削除し、`gas/Code.gs` の内容を貼り付けます。
3. 左側の「プロジェクトの設定」を開き、「スクリプト プロパティ」に次を追加します。

   - プロパティ：`SETUP_KEY`
   - 値：自分だけが知っている長いランダム文字列

   この値は初回の管理者パスワード登録に一度だけ使います。公開しないでください。

4. 関数一覧から `initializeProject` を選んで実行し、スプレッドシート作成などの権限を許可します。
5. 実行ログにエラーがなく、スクリプトプロパティに `SPREADSHEET_ID` が追加されたことを確認します。
6. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選択します。
7. 次のように設定してデプロイします。
   - 次のユーザーとして実行：自分
   - アクセスできるユーザー：全員
8. 表示された `/exec` で終わるウェブアプリURLをコピーします。

スプレッドシートはスクリプト実行者のGoogleドライブ内に作成されます。位置情報を保存するシートを公開共有しないでください。

## 2. Cloudflare Workerを準備

1. Cloudflareにログインし、「Workers & Pages」からWorkerを新規作成します。
2. Workerのコード編集画面を開き、`cloudflare/worker.js` の内容を貼り付けます。
3. ファイル先頭の次の値を変更します。

   - `GAS_URL`：手順1でコピーしたGASの `/exec` URL
   - `FRONTEND_ORIGIN`：GitHub Pagesのオリジン

   このリポジトリでGitHub Pagesを使う場合、通常は次の値です。

   `https://a09848281-prog.github.io`

   最後に `/gps-control-center/` のようなパスは付けません。

4. 保存してデプロイします。
5. `https://<Worker名>.<アカウント名>.workers.dev/health` を開き、JSONで `ok: true` が返ることを確認します。
6. WorkerのベースURLを控えます。例：`https://my-gps-redirect.<アカウント名>.workers.dev`

## 3. GitHub Pagesを有効化

1. このリポジトリの「Settings」→「Pages」を開きます。
2. 「Deploy from a branch」を選びます。
3. Branchを `main`、Folderを `/(root)` にして保存します。
4. 公開されたGitHub PagesのURLを開きます。

## 4. 初回ログイン設定

1. 管理画面の「Cloudflare Worker URL」に、WorkerのベースURLを入力して保存します。
2. 初期設定欄に、GASのスクリプトプロパティに設定した `SETUP_KEY` と、これから使う管理者パスワードを入力します。
3. 管理者パスワードは10文字以上にしてください。
4. 初期設定後、管理者パスワードでログインします。

セットアップキーは管理者パスワードの登録後にGAS側で自動削除されます。管理者パスワードは公開HTMLやWorkerコードには保存されません。

## 5. URLを発行

管理画面で設定します。

- URLに入れる好きな文字：日本語・英数字・ハイフン・アンダーバー、1〜50文字
- 相手画面の表示文：1〜200文字
- リダイレクト先：HTTPSのみ
- 有効期限：空欄なら期限なし
- リダイレクト待ち時間：0〜30秒

発行後に表示されるURLをコピーして共有します。

## HTTP 301について

`/go/<識別文字>` の応答は本物のHTTP 301です。301は通常、恒久的な移動を示し、ブラウザや中継キャッシュに記憶される場合があります。

このアプリでは、URLの無効化・有効期限を毎回確認できるように、301応答へ `Cache-Control: no-store` を付けています。そのためステータスコードは301ですが、ブラウザに転送先を保存させない設定です。

また、位置情報の許可画面を先に表示する必要があるため、共有URL `/r/<識別文字>` は最初の応答では301ではなく説明ページ（HTTP 200）です。本人が位置情報を許可し、記録が成功したあとに `/go/<識別文字>` が301を返します。

## 画面・プライバシー

- 取得画面は白背景・文字中心です。
- ブラウザ標準の位置情報許可を利用します。
- 許可されなければ位置情報は送信されず、指定先へも移動しません。
- 位置情報は管理者用スプレッドシートへ保存されます。
- 相手に位置情報の取得・送信・移動先を事前に説明する文を必ず表示します。
- 取得した緯度・経度は正確な個人情報です。管理者はスプレッドシートの共有範囲とアカウントを安全に管理してください。

## 制限・注意

- URL識別文字は重複できません。
- URL識別文字に `/` や空白は使えません。
- 転送先はHTTPSのみです。
- 管理者ログインセッションは最長6時間です。
- 301応答を返すのは位置情報の記録後です。初回ページ表示前に301を返す動作ではありません。
- GitHub Pages・GAS・Cloudflareの各サービス側の仕様や利用制限に従ってください。
